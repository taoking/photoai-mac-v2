# 迭代

> 第一个阶段版本 **0.6.0**（2026-11-20）包含计划里的 M1–M6，加上应用图标和检查器的直方图、导航器。
> 之后的所有改动（用户反馈、遗留的验证、新功能）都在本文件里管理：先进“待办”，排进某个迭代再做，做完记进“迭代记录”。
> [计划](计划.md) 保留 M1–M6 的原始范围和验收，不再往里加新阶段。

## 规则

- **待办**：每一项一个编号 `B-<n>`，写清来源（用户原话或哪份验收记录的 NOT RUN）、谁来做、状态（待做 / 进行中 / 完成 / 不做）。编号不复用。
- **迭代**：从待办里挑几项组成一个迭代 `I-<n>`，一个分支 `iter-<n>-<主题>`，一份验收记录 `docs/验收/I-<n>-<主题>.md`（每项 PASS / NOT RUN / BLOCKED 附证据），一个 PR。用户说“直接合并”时可以由 Claude 合并，否则等用户合并。
- **影响流畅度的改动**：改之前、改之后各跑一次 `Scripts/inspector-pf.sh`（PF-2、PF-6、PF-7），两次的结果都写进验收记录；明显变差就不合并。
- **阶段版本**：攒够一批有用的改动后发一个版本：改 `Resources/Info.plist` 的版本号、`Scripts/release.sh <版本>` 打包、在 GitHub 发 Release，在下面的“版本”表加一行。
- 每次结束工作前照旧：沟通记录追加用户原话、设计稿和细节文档同步、本文件更新状态、[交接](../交接.md) 更新“现在在哪一步”和“下一步”。
