# 产品定位与目标

> 状态：v0.5（2026-11-19），产品规则已全部与用户确认。标“建议”的是尚未确认的讨论材料。

## 1. 一句话定位

**一个只给自己用的本机选片工作台，同时是所有导入过照片的预览档案：记住每张照片在哪张卡、哪块盘上，在本机永久留一份预览；卡和盘拔掉以后照样能浏览和选片，选好的照片归进收藏夹，再导出原文件去别处精修。**

它不做调色和修图，也从不改动、移动、删除卡和外置盘上的文件。

## 2. 已确定

| 项目 | 结论 |
| --- | --- |
| 定位 | 选片工作台 + 所有已导入照片的预览档案 |
| 用户 | 只有自己用，不考虑分发、签名公证、多语言、首次引导 |
| 规模 | 算上重复导入、反复导入，约 5 万到 10 万条 |
| 素材 | 主要是相机照片；基本不会出现“同名但不是同一张” |
| 存储介质 | 多张存储卡 + 多块外置盘，经常插拔 |
| 旧数据 | 全新开始，不迁移 v1 的 Catalog |
| 第一版功能 | 卷清理（清卡）、人物搜索、OCR 搜索 |
| 晚一点再加 | Apple Photos 来源 |
| 速度取舍 | 导入慢可以接受；人物与 OCR 在导入后异步完成 |
| 照片身份 | 同一张照片在多处出现算**一张**，名下挂多个位置。**名字不同一定不是同一张**；名字相同时按拍摄时间判断，没有拍摄时间按文件大小 |
| 分类 | 星级表示好坏，**标签**表示类别（人像、风景、经典等，用户自定义）；一张照片可以有多个标签；两者可组合筛选 |
| 收藏 | 不做单独的“收藏”（心形），用标签代替 |
| 连拍 | 第一版不做连拍分组，网格里每张单独显示 |
| RAW + JPEG | 同编号、同拍摄时间的 RAW 和 JPEG 合成一组，打星、标记、收藏夹一起生效；**预览优先用 JPEG 生成**，没有 JPEG 才用 RAW |
| 编号循环 | 身份带拍摄时间，不会合错；命令行按编号命中多张时，**取拍摄时间最晚的一张** |
| 卷识别 | 按卷 UUID 识别，用户给每张卡、每块盘起名字 |
| 离线卷 | 拔着但没在软件里移除的卷，照样算有关联 |
| 清卡 | 提供“找不到副本”检查，但允许无视检查继续移除（可能另有软件不知道的备份） |
| 清理即隐藏 | 移除卷、重扫发现文件不在，都**不删除**缩略图、预览和照片曾经所在卷的记录；照片的所有位置都失效后，它从常规列表和搜索中隐藏 |
| 真正删除照片 | 只在单独的“无卷关联照片”界面里进行；已移除的卷也只在这个界面里出现 |
| 重扫 | 删掉的照片重扫时会重新导入，由用户自己管理，不做忽略名单 |
| 外部接口 | 命令行工具直接写数据库；默认在软件关闭时使用，开着用的副作用用户接受；设计上优先保证软件在不用命令行时正常工作 |
| 地点 | 免费就把坐标转成地名并缓存到记录里，不免费就不做；重要性低 |
| 预览备份 | 放内置盘，接受 10 万张约 44 GB 的占用 |
| 源文件 | 软件里的任何删除都只作用于本机，绝不碰卡和外置盘上的源文件 |
| 去向 | 导出原文件到别处精修 |

## 3. 核心工作流

```text
插卡 / 插盘
→ 导入：建索引，生成缩略图和预览备份（慢可以接受）
→ 后台：人物、OCR、地名（异步，不阻塞选片）
→ 选片：按卷 / 日期 / 地点 / 人物 / 相机浏览；打星、打标签、Pick/Reject
→ 筛出：按星级 + 标签筛选，例如“经典 + 5 星”
→ 归集：把选中的照片加入收藏夹
→ 导出：从当前在线的卡或盘复制原文件到精修目录
→ 清卡：查看清卡检查结果后格式化，在软件里移除这张卡
→ 定期整理：在“无卷关联照片”里决定哪些预览不再需要，真正删除
```

### 3.1 照片、卷与位置

- **卷**：每张卡、每块盘是一个卷，按卷 UUID 识别，用户可以起名字，比如“卡 A 128G”“备份盘 2”。卷有三种状态：
  - 在线：插着；
  - 离线：拔了，但还在用，照片照常显示；
  - 在线 / 离线只看卷有没有挂载，不逐个检查原片（见设计稿 §4.1）；
  - 已移除：用户在软件里移除了这个卷，通常是卡已经清空。
- **位置**：照片在某个卷上的路径。位置分两种：
  - 现存：卷在线或离线，且上次扫描时文件还在；
  - 历史：卷已移除，或重扫时发现文件已经不在了。历史位置保留卷名、路径和最后一次见到的时间。
- **照片**：评分、标记、收藏夹、人物、OCR、缩略图和预览都挂在照片上，不挂在位置上。重复导入只会多一个位置，不会多一条照片，也不会多一份预览。
- **可见性**：照片至少有一个现存位置才出现在常规列表、搜索和收藏夹里；否则只出现在“无卷关联照片”界面。
- 检查器只显示照片现在在哪些卷上。导出原文件时，软件告诉我该插哪张卡或哪块盘。

### 3.2 清卡

1. 选中一张卡，软件列出这张卡上**没有其他现存副本**的照片，并标出其中已打星、已 Pick、已进收藏夹的。
2. 可以直接把这些照片的原文件复制到别的盘（就是一次导出），复制完重扫目标盘，它们就有了副本。
3. 全都有副本，提示可以放心清空。
4. 不论检查结果如何，都可以确认后继续移除这张卡。
5. 移除后，这张卡上的位置全部变成历史位置；照片、评分、收藏夹、缩略图和预览原样保留。没有其他现存位置的照片从常规列表中隐藏，出现在“无卷关联照片”里。

### 3.3 选片与归集

- 相机照片的拍摄时间是连续的，按卷、按日期浏览是主路径。
- 一边看一边打星和标签：星级表示好坏，标签表示类别，一张照片可以有多个标签。
- 按星级和标签组合筛选，全选后放进新建的收藏夹，在收藏夹里再增减，最后导出。完整例子见 [信息架构与交互 §3.0](信息架构与交互.md)。
- 人物、地点是辅助筛选条件。
- 收藏夹只存引用，不复制文件；一张照片可以在多个收藏夹里。
- 导出时可以按收藏夹保持分组，比如每个收藏夹导出成一个子文件夹。

### 3.4 外部接口（命令行工具）

- 按文件名（`DSC01926.ARW`）、去掉扩展名的文件名，或编号（`01926`、`1926-1950`）批量打星。
- 用同样的匹配方式批量加入已有收藏夹，或新建一个收藏夹。
- 一个编号命中多张时，取拍摄时间最晚的一张，并在输出里列出被跳过的；匹配不到的也要列出来。
- 只匹配可见照片，也就是至少有一个现存位置的照片。
- 通过 Claude skill 调用，例如 `photoai rate 5 1926-1950`、`photoai collect "新疆精选" 1926 1931`。

**处理原则：** 软件在不用命令行时的正常使用优先。只做两件几乎零成本、对软件本身也有好处的事：

- 软件按字段写入，不整行覆盖。这本来就是正确的写法，顺带避免冲掉命令行的改动。
- 窗口重新获得焦点时检查数据库有没有被外部改过，改过才重读。没改动时只是一次很轻的检查。

其余影响一律接受，不为它增加复杂度：同一张照片同一字段两边同时改时后写的赢；在软件里撤销更早的评分会覆盖命令行的改动；数据库短暂锁定时两边稍等重试。检测到软件在运行时，命令行工具只提示、不阻止。

### 3.5 删除与清理规则

本机里有三层东西：照片（含缩略图、预览、评分、收藏夹等）、位置、卷。卡和外置盘上的源文件永远不动。

| 操作 | 照片与预览 | 位置 | 卷 |
| --- | --- | --- | --- |
| 移除一个卷（清卡） | 不动；没有现存位置的照片被隐藏 | 这个卷上的位置全部变为历史位置 | 标记为已移除，保留名称 |
| 重扫发现文件已不在 | 不动；没有现存位置的照片被隐藏 | 这个位置变为历史位置 | 不动 |
| 导出、100% 放大、清卡核对时读不到原片 | 不动；没有现存位置的照片被隐藏 | 这个位置变为历史位置 | 不动 |
| 重扫发现文件又回来了 | 照片恢复可见，评分等全部还在 | 恢复为现存 | 不动 |
| 在“无卷关联照片”里删除 | **删除照片记录、缩略图、预览** | 一并删除 | 不再有照片的已移除卷一并删除 |

常规界面里**没有删除照片的入口**：照片只要还有现存位置，就说明它的卡或盘还在用，删了下次扫描也会回来。

**移除后的卷重新插上**：已移除的卷不会自动恢复。重新添加时它被当作一个新卷扫描：没在“无卷关联照片”里删掉的照片，会按身份对上原来的记录，恢复可见，评分和收藏夹都在；已经删掉的照片作为新照片重新导入。

**“无卷关联照片”界面：**

- 从菜单单独打开，常规侧栏和列表里看不到。
- 列出所有没有现存位置的照片，按曾经所在的卷、日期分组，标出已打星、已 Pick、已进收藏夹的。
- 可以单张、多选或整组删除，删除前确认一次。这是软件里唯一会删掉照片预览的地方。

## 4. 不做（第一版）

- 调色、RAW 调整、LUT、裁剪、批量渲染导出：这些交给精修软件。
- 连拍分组。
- 相似照片、重复照片的清理建议。“一张照片多处副本”现在是正常状态，只在清卡检查里作为“有副本”的依据。
- 视频管理。
- 旧 Catalog 迁移。
- Apple Photos 来源：之后再加。
- 多用户、云同步、分发相关的签名公证、多语言。
- 任何修改、移动或删除源文件的操作。
- 删除照片的忽略名单。

## 5. 规模与存储估算

用 v1 实测的平均大小估算（480 缩略图平均 52.4 KB，1600 预览平均 389.9 KB）：

| 预览备份规格 | 每张 | 5 万张 | 10 万张 |
| --- | --- | --- | --- |
| 只存缩略图 480 | 约 52 KB | 约 2.6 GB | 约 5.2 GB |
| 缩略图 + 1600 预览（已确定） | 约 440 KB | 约 22 GB | 约 44 GB |

照片按“一张多位置”去重、RAW + JPEG 合组后，预览只存一份，实际占用按不同照片数计算，会少于上表。由于移除卷不删预览，占用只增不减，直到在“无卷关联照片”里手动删除。

## 6. 地点

- **免费方案**：用 MapKit 的反向地理编码，免费但需要联网，会把坐标发给 Apple，系统还会限制请求频率。macOS 26 起 `CLGeocoder` 已由 `MKReverseGeocodingRequest` 取代，具体接口要在本机 SDK 上实测。
- **控制请求量**：坐标按约 1 公里的网格取整，一个网格只查一次并缓存。相机照片高度聚集，10 万张实际只需要几百到几千次请求，在后台慢慢查。
- **可选的离线方案**：内置 GeoNames 城市数据（免费，CC-BY），完全离线，但只能精确到城市。
- 设置里单独开关，默认关闭；照片没有 GPS 就跳过。国内坐标偏移和中文地名的效果要用真实照片验证。

## 7. 从 v1 带过来的经验

这些是 v1 踩坑后测出来的结论，新版直接沿用：

- **降采样优先用内嵌预览。** 强制全图解码一张冷 ARW 实测要 30 秒；但 JPEG 只内嵌 160 px 的 EXIF 缩略图，内嵌图不到请求尺寸一半时要回退全解码。
- **1600 预览对 Sony ARW 零损失。** ARW 内嵌预览是 1616×1080。
- **预览备份不是可丢弃的缓存。** 卷离线、移除后，它就是照片在本机的唯一表示，要放在 Application Support，不能放 Caches，也不能被自动淘汰。
- **重扫按文件大小 + 修改时间跳过未变的文件。** 首次扫描并行读元数据，48 张冷 ARW 实测从 34.6 秒降到 6.8 秒。
- **exFAT 卷重新插回时修改时间会漂移。** 身份判断不能依赖修改时间。
- **评分等高频改动按行、按字段写 SQLite。** 不整库重写，也不整行覆盖。
- **SwiftUI 网格不要让每个格子监听整个图库对象。** v1 为此叠了好几层刷新补丁，新版用 `@Observable` 按属性追踪。
- **全屏模式不要做成盖在图库上的多层覆盖。** v1 的“返回后网格空白”就出在这里。
