## 路线

```text
P0 可点击原型 → 按原型反馈修订设计稿 → M1 … M6 原生应用
```

## 性能目标

用户的要求是“按合理的来”。下面是建议值，作为各阶段的验收项；实测证明某项不现实时，带着数据在沟通记录里说明并调整，不能悄悄放宽。合成数据统一用 10 万条照片、6 个卷、其中 30% 有两处副本。

| 编号 | 场景 | 目标 | 阶段 |
| --- | --- | --- | --- |
| PF-1 | 冷启动到网格可见 | ≤ 2 秒 | M1 |
| PF-2 | 网格快速滚动 | 无明显卡顿；主线程单帧目标 < 16 ms，用 Instruments 抽查 | M1 |
| PF-3 | 切换侧栏项：卷、日期在 M1 测；收藏夹在 M2 收藏夹做好后测 | ≤ 200 ms | M1 / M2 |
| PF-4 | 已知的卡插上后自动重扫 1,000 张未变化的照片 | ≤ 3 秒 | M1 |
| PF-5 | 真实卡首次导入 | 记录总耗时和每张预览平均耗时，作为基线，不设门槛 | M1 |
| PF-6 | 打星、打标签、标记后界面反应 | ≤ 50 ms | M2 |
| PF-7 | 单张视图翻页（预览已在本机） | ≤ 100 ms | M2 |
| PF-8 | 对 10 万条重新筛选 | ≤ 100 ms | M2 |
| PF-9 | 导出吞吐 | 记录基线（MB/s），不设门槛 | M3 |
| PF-10 | 移除一个含 1 万张照片的卷 | ≤ 1 秒 | M4 |
| PF-11 | 清卡检查 1 万张，在线副本在 SSD 上 | ≤ 10 秒 | M4 |
| PF-12 | 后台人物、OCR 运行时 | PF-2、PF-6、PF-7 不退化 | M6 |

## P0 可点击原型

**形式：** 单个 HTML 文件 `prototype/index.html`，不依赖网络，用浏览器直接打开。照片用生成的色块代替，数据是模拟的约 1,200 张照片、4 个卷。

**要验证的问题：**

- [x] 典型场景能不能顺手走完：单卡 → 时间倒序 → 边看边打星、打标签 → 筛选“经典 + 5 星” → 全选 → 新建收藏夹 → 增减 → 导出。
- [x] 键盘：1–5、6–9、⌥1–⌥9、P / X / U、空格、C、B / ⇧B、⌫、⌘A、⌘Z、自动前进（⇪）是否好记、好按。
- [x] 筛选条：同类“或者”、不同类“并且”是否符合直觉；“打星过程中结果保持不变 + 刷新结果”是否顺手。
- [x] 侧栏每一项各自记住筛选条件，是否符合预期。
- [x] 网格、单张、比较三种视图切换时，滚动位置和选择是否保留。
- [x] 卷：在线 / 离线 / 移除，清卡检查的信息是否够做决定。
- [x] 移除卷后照片隐藏、“无卷关联照片”窗口里删除，这套规则用起来是否清楚。
- [x] 导出面板的三个选择是否够用。

**不在原型里做：** 真实照片、真实文件读写、搜索的自然语言、人物和 OCR 的真实识别、命令行工具。

**验收：** 用户在原型上走完典型场景，把意见写进 [沟通记录](沟通记录.md)，并同步修订设计稿。

**结果（2026-11-19）：PASS。** 用户确认“当前设计 ok”“原型交互确认”。两轮反馈已并入设计稿 v1.2。

## M1 工程骨架 + 卷与导入

- SwiftPM 工程，分 `PhotoAICore` / `PhotoAIApp` / `photoai` 三个目标。
- **先做数据层**：照片、文件、位置、扫描目录四张核心表，可见性计数和历史位置的转换都在事务里（见 [数据模型](数据模型.md) §3–§6），按字段写入，写入失败可见。
- 认卷（UUID）、添加卷、按目录扫描（存储卡默认 `DCIM`，外置盘手动选）、只对完整扫完的目录确认缺失、重扫跳过未变文件、历史位置重新出现时恢复、同路径换片、照片身份与 RAW + JPEG 合组。
- 生成 480 缩略图 + 1600 预览（优先 JPEG），后台进行，可暂停；分别显示“已收录”和“离线预览就绪”两种进度。
- 网格：原比例、按天分组、离线也能显示。

**进度（2026-11-19）：** 代码完成，自动测试 32 项通过；真实卡、外置盘、索尼 ARW 样片的检查待用户补做。详见 [M1 验收记录](验收/M1-卷与导入.md)。

- [x] SwiftPM 工程三个目标；数据层与测试
- [x] 认卷、添加卷、按目录扫描、历史位置恢复、同路径换片、RAW + JPEG 合组
- [x] 480 + 1600 预览，后台、可暂停；“已收录”与“离线预览就绪”分开显示
- [x] 网格：原比例、按天分组、离线也能显示
- [x] 十万条合成数据：PF-1、PF-2（替代测量）、PF-3（卷、日期）、PF-4
- [ ] 真实卡与外置盘导入、真实卡 PF-4 / PF-5、索尼 ARW 样片、PF-2 Instruments、重启后的 PF-1

**验收：**

- 数据层测试（从原 M4 提前）：历史位置转换、可见性计数、移除卷、扫描中断（含两个子目录的卷，在第二个子目录前中断，未读部分的照片、位置、收藏夹可见性都不变）、“原样放回，旧评分恢复”、“同路径换片，新片不继承旧评分”、子目录整个被删。
- 预览就绪：生成中拔盘、中途退出、写满，重启后能识别缺失档位，重插时续做；断开源卷后，用实际能解码的 480 和 1600 图片数核对“离线预览就绪”的计数。
- 真实 RAW + JPEG 样片：记录 EXIF 原始字段和实际合组结果。
- 用真实卡和外置盘导入；拔掉后照常浏览；重新插上不重复导入。
- PF-1、PF-2、PF-3（卷、日期）、PF-4、PF-5：十万条合成数据测查询与界面；真实卡测 PF-4、PF-5，并记录卷格式、冷 / 暖状态、预览就绪数和样本数量。

## M2 选片

- 单张视图、比较视图，与网格在同一区域切换。
- 星级、标签（自定义、多个）、Pick / Reject；自动前进；撤销 / 重做。
- 筛选条与“结果保持不变 + 刷新”；侧栏各项记住筛选条件。
- 收藏夹：新建、加入、移出、改名、删除。
- 快捷键只定义一处，文本框获得焦点时让位。

**验收：** 在真实照片上走到“筛选 → 新建收藏夹 → 增减”，交互与原型一致（导出留到 M3 联验）；重启后核对评分、标签、收藏夹成员与撤销范围；1,000 张连续打星不卡顿；PF-3（收藏夹）、PF-6 至 PF-8。

## M3 导出

- 导出面板：范围 × 文件 × 目录结构；只复制、不覆盖、同名自动改名。
- 每个文件依次尝试所有在线位置，都读不到才算失败；读不到的位置改为历史，界面随即刷新。
- 列出需要插哪些卷；离线卷上的照片可跳过；面板里用户的选择保持不变。

**验收：** 导出后源文件字节不变；逐项核对目标文件的内容、数量和目录；覆盖目标已有同名文件、第一个位置读不到而第二个在线位置成功、复制中断后重试；只把确实复制完成的文件计入成功；真实照片走完整个典型场景（含导出）；PF-9。

## M4 清卡与无卷关联照片

- 卷详情、清卡检查（按文件分三类 + 预览就绪）、补副本（保留原名、冲突换子目录、SHA-256 校验、重扫登记）、移除卷。
- “无卷关联照片”窗口与删除（确认时重新核对）。
- 移除后的卷重新插上，照片对回原记录。

**验收：**

- 按 [设计稿](设计稿.md) §4 的每条规则各写一个测试，§5 的核对结论单独验。
- 清卡三种情况：副本全在线、副本全离线、只缺 RAW（备份盘只有 JPEG）。只有全部核实且预览就绪才显示“可以清空”。
- 补副本：源文件已被删、目标只有 JPEG、目标盘写满、目标已有同名不同照片（旧目标字节不变，重扫后原照片获得正确的第二个位置，评分与照片总数正确）。
- 从打开“无卷关联照片”到确认删除之间，被重扫找回的照片不删。
- 用真实卡走一遍“检查 → 补副本 → 移除 → 重新插上”；PF-10、PF-11。

## M5 命令行工具 + skill

- `photoai rate`、`photoai collect`、`photoai find`：文件名 / 编号 / 范围匹配，命中多张取最晚，报告跳过和未匹配。
- 软件窗口获得焦点时检查外部改动。
- Claude skill 封装。

**验收：** 软件关闭时批量打星后打开软件，星级正确；软件开着时使用，界面在切回窗口后刷新；覆盖 `find`、`collect`、编号循环、无匹配、隐藏照片不被匹配、两个进程写不同字段互不覆盖（同字段后写的赢，已接受）。

## M6 后台分析与搜索

- OCR、人物（含特征向量）、地名（默认关闭）。
- 全局搜索：文件名 / 编号、日期、相机、镜头、标签、人物、地点、OCR 文字。

**验收：** 分析可暂停、可续跑；用一组已知内容的本机照片验证能搜到指定人物、指定一行 OCR 文字、指定月份（如 `2026-08` 必须按日期而不是编号解析），无关照片和隐藏照片不命中；PF-12 用同一份数据、同一台机器、同样的操作比较后台分析开和关。

## 工作方式

- 每个阶段一个分支，如 `m1-volumes-import`；用约定式提交（`feat:` / `fix:` / `test:` / `docs:` …）；完成后开 PR，由用户确认合并到 `main`。
- 每个阶段一份验收记录 `docs/验收/M<n>-<主题>.md`：每项检查记为 **PASS / NOT RUN / BLOCKED**，附证据（命令、输出、数据）。需要真实卡或硬件而当时没有的，如实记 NOT RUN。
- 完成一项就在本文件打勾、在“进度记录”加一行；同时更新 [交接](../交接.md) 的“现在在哪一步”。
