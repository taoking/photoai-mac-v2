## 1. 定位

一个只给自己用的本机选片工作台，同时是所有导入过照片的预览档案：

- 记住每张照片在哪张卡、哪块盘上；
- 在本机永久留一份预览，卡和盘拔掉、清空以后照样能浏览和选片；
- 选好的照片归进收藏夹，再导出原文件去别处精修。

不做调色修图；从不改动、移动、删除卡和外置盘上的文件。

## 2. 规模与前提

- 只有自己用；约 5 万到 10 万条；主要是相机照片。
- 多张存储卡、多块外置盘，经常插拔。
- 全新开始，不迁移 v1 数据；不开 App 沙盒。
- 预览放内置盘：480 缩略图 + 1600 预览，10 万张约 44 GB。

## 3. 核心概念

| 概念 | 规则 |
| --- | --- |
| 照片 | 一次拍摄。名字不同一定不是同一张；名字相同时按拍摄时间（**精确到秒，不用亚秒**）认定，没有拍摄时间按文件大小。同编号、同拍摄时间的 RAW 和 JPEG 合成一张，预览优先用 JPEG 生成 |
| 文件 | 照片的一个格式成员：RAW、JPEG 各是一个文件。**副本按文件算**，不按照片算 |
| 卷 | 一张卡或一块盘，按卷 UUID 识别，用户起名。状态：在线、离线、已移除 |
| 位置 | 某个文件在某个卷上的路径。现存：卷在用且文件还在；历史：卷已移除或文件已不在 |
| 星级 | 0–5，表示好坏 |
| 标签 | 用户自定义的类别（经典、人像、风景……），有颜色和快捷键；一张可以有多个 |
| Pick / Reject | 留用 / 淘汰标记 |
| 收藏夹 | 手动归集的照片引用，一张可以在多个收藏夹里 |

不做：心形收藏、自由文本颜色标签、备注、连拍分组、相似 / 重复清理建议、调色、视频。

## 4. 可见性与删除

- 照片至少有一个现存位置才出现在常规列表、搜索、收藏夹和命令行里；否则只出现在“无卷关联照片”窗口。离线但没移除的卷算有关联。
- 移除卷（清卡）、重扫发现文件不在：位置变成历史位置，**不删照片、预览、评分和收藏夹**。
- 常规界面没有删除照片的入口。真正删除只在“无卷关联照片”窗口里做，已移除的卷也只在这里出现。
- 删掉的照片重扫时会重新导入，不做忽略名单。
- “无卷关联照片”窗口里确认删除时，按当时的状态重新核对一次：从打开窗口到确认之间被重扫找回的照片不删。

### 4.0 扫描的规则

- **只对完整扫完的目录下结论。** 扫描按目录进行，一个目录完整列出后，这个目录里“这次没见到”的文件才改为历史位置。中途拔卡、取消、目录读不了（权限、读写错误）时，没扫完的目录保留上次的结果，照片照常可见；状态栏提示“卡 A 有 3 个目录没扫完”，下次插上自动续扫。父目录完整列出、但某个子目录已经不在，这个子目录下的文件才算确实消失。
- **历史位置重新出现要恢复。** 重扫时，历史位置对应的文件又出现在原路径、身份相同，就恢复为现存，评分、收藏夹随照片回来。不能因为“大小和修改时间没变”而跳过。
- **同一路径换了照片。** 同一路径上的文件身份变了（比如卡上删光后编号重置），旧位置改为历史，新文件挂到它自己的照片上；新照片不继承旧照片的评分。
- **收录和离线预览就绪是两种状态。** 照片进网格只代表已收录；480 和 1600 两档预览都写完并能解码，才算离线预览就绪。卷详情同时显示两种进度；没就绪的照片在卷重新插上时续做。

### 4.1 在线 / 离线与原片被手动删除

- **在线 / 离线只看卷有没有挂载**（按卷 UUID 对上），不逐个检查原片。挂载和卸载由系统通知推送，几乎不耗资源；逐个检查 10 万个文件在存储卡上要几十秒，不做。
- 因此在 Finder 里手动删掉原片后，软件**暂时不知道**，照片照常显示（预览在本机）。软件不监听文件变动，也不主动定期扫描。发现的时机只有这些：
  1. 重新扫描，包括已知的卷插上时的自动重扫；
  2. 导出或 100% 放大时读不到原片：这一张单独报错，其余照常导出；
  3. 清卡检查时现场核对副本（见 §5）。
- 发现后：这个位置改为历史位置。照片还有其他现存位置就照常显示；没有就进入“无卷关联照片”。星级、标签、收藏夹、预览都保留。文件放回去再重扫，照片恢复可见。
- 单张视图在后台换原图（§7.3）读不到时只是留在预览，**不算**发现的时机：那是看照片时自动发生的，不应该悄悄改动照片的位置。
- RAW + JPEG 只删了其中一个文件时，照片仍然可见，导出时只导出还在的那个。
- 移除后的卷重新插上算新卷；没被删掉的照片会对回原记录并恢复可见。

## 5. 清卡

1. **按文件判断。** 卡上的每个文件（RAW、JPEG 分开算）归入三类之一：
   - **已核实**：其他在线卷上有这个文件的副本（同名、同拍摄时间、同大小），当场确认文件还在；
   - **只有离线记录**：副本只在离线卷上，按上次扫描结果，没法当场核对；
   - **缺副本**：别处没有。备份盘只有 JPEG、RAW 只在卡上时，这张照片算缺副本，并注明缺的是 RAW。

   另外单独列出离线预览还没就绪的照片。已打星、已 Pick、已进收藏夹的照片在各类里标出来。
2. **只有卡上所有文件都“已核实”、并且预览全部就绪，才显示“可以清空”。** 否则只显示各类数量；“只有离线记录”的提示可以插上那块盘再核对。
3. **补副本**：把缺副本的文件复制到用户选的卷。
   - 保留原文件名，同一张照片的 RAW 和 JPEG 放在同一目录。
   - 目标已有同名文件时不改名，换一个新的子目录（如 `补副本-2026-11-19/`），目标上已有的文件一字节都不动。
   - 复制时算源文件的 SHA-256，写完读回目标再算一次，两者相同才算成功；之后重扫目标目录登记副本。
   - 源文件读不到、目标盘写满、校验不一致的文件单独列出，不算成功。
4. 不论结果如何，都可以确认后移除这张卡；确认框里重复三类数量。

补副本和“导出给精修”不是一回事：导出遇到同名会自动改名（目标通常不在任何已扫描的卷上），补副本绝不改名，否则重扫时会因“名字不同”被建成另一张照片，原照片仍然缺副本。

## 6. 主要界面

- 一个窗口：侧栏（图库、时间、卷、收藏夹、人物、地点）+ 内容区 + 检查器 + 状态栏。
- 内容区顶部尽量薄：一行 36 px 的标题行（标题、卷在线状态、“N 张无副本”提醒、筛选摘要、计数、“⋯”更多操作）+ 一行筛选条。筛选条可用 `\` 或工具栏“筛选”收起，收起后生效的条件以摘要显示在标题行。
- 单张、比较、放大共用一套观看样式（“显示”菜单）：背景深灰（默认）/ 黑 / 中灰 / 白，不跟系统深浅色走；照片细边框和投影（默认开）；四周留白窄 / 宽。记在本机设置里。网格不跟着换。
- 单张视图在一张照片上停约 0.3 秒、原片所在卷在线时，后台按屏幕尺寸读原图换掉 1600 预览，再读后一张、前一张；翻页不等它。卷离线或读不到时留在预览。
- 单张、比较视图收起标题行和筛选条；单张视图的信息条浮在画面底部，鼠标不动 2 秒后淡出，打星、打标签时短暂出现。`F` 专注模式再隐藏侧栏、检查器和工具栏。
- 内容区三种视图：网格 / 单张 / 比较，在同一块区域里切换，不叠覆盖层；切换时保留滚动位置和选择。
- 网格：缩略图按原比例完整显示；按天分组；每张单独一格。
- 筛选条：星级、标签、Pick / Reject 点一下即生效；同类“或者”、不同类“并且”；打星过程中结果保持不变，点“刷新结果”才重新筛；侧栏每一项各自记住筛选条件。
- 导出面板：范围（所选 / 当前结果 / 收藏夹）× 文件（RAW / JPEG / 两者）× 目录结构（平铺 / 按收藏夹 / 保持原目录）；只复制、不覆盖。每个文件依次尝试所有在线位置，都读不到才算失败；读不到的位置改为历史。用户的选择（比如是否跳过离线卷）在面板里保持不变。
- 后台任务（扫描、预览、人物、OCR、地名）在状态栏显示进度，没有任务时隐藏；交互请求永远优先。

### 6.1 检查器（0.6.0，用户 2026-11-20 反馈）

- 从上到下：**导航器**（只在单张视图放大时）→ **直方图** → 拍摄参数一行（焦距、光圈、快门、ISO）→ 选片（星级、标记、标签、收藏夹）→ 文件（文件名、格式、拍摄时间、相机、镜头、尺寸）→ 识别 → 现在在 → 预览。
- 导航器：整张照片的小图，白框是正在看的部分，框外压暗；点或拖动小图，画面跟过去，框不出照片。比较视图不显示。
- 直方图：红绿蓝叠加、白线是亮度，按 480 缩略图算（RAW 是相机内嵌的 JPEG，和相机屏幕上的一样）；高光溢出、暗部死黑超过 0.5% 时提示。在一张照片上停 0.12 秒才在后台算，快速翻页不算中间的。
- 用户的前提是“如果我的想法比较影响性能可以不做，当前用起来特别流畅”：改前改后测了 PF-2、PF-6、PF-7，在波动之内。
- 应用图标：深蓝圆角方底、两张叠着的照片、一颗金色的星，由 `Scripts/make-icon.swift` 画出。

| ⌘+ / ⌘− / ⌘0 | 放大一档、缩小一档（适合窗口 / 50% / 100% / 200%）/ 适合窗口；触控板捏合任意比例 |

### 7.1 M2 实现时定下的细节

- **撤销范围**：星级、标签、标记、加入 / 移出收藏夹可以撤销；只在本次运行内，重启后清空。新建、改名、删除收藏夹，标签设置，扫描、移除卷都不进撤销（删收藏夹前确认一次）。别的进程（命令行）改过库时撤销记录清空。
- **值没变时再按一次**（比如已经 3 星又按 3）：不写库、不进撤销，但照样自动前进。
- **结果保持不变**：打星、打标签时结果不变；后台扫描、预览生成刷新网格时也不重新筛，只把新出现且符合条件的照片加进来。点“刷新结果”或改条件才重新筛。
- **Caps Lock**：开着时字母是大写的，快捷键按小写字母认，`P` 仍是 Pick，`⇧P` 要按 ⇧。
- **`Z` 放大到 100%** 和比较视图的同步缩放移到 M3：要读原文件，和导出一起做（读不到原片时按 §4.1 处理）。

### 7.2 M3 实现时定下的细节

- **什么叫“读不到原片”**：只有卷仍挂在原来的位置（卷 UUID 没变）、文件却不存在，才把这个位置改为历史（§4.1）。读到一半出错、没有权限、文件大小和上次扫描时不一样、卷刚被拔掉，都只在结果里报告，位置照旧。理由同 §4.0：拔卡时路径也会消失，不能当成文件被删。
- **同名**：改名为 `名字 (2).扩展名`，同一张照片的 RAW 和 JPEG 用同一个编号。目标里已有内容逐字节相同的同名文件时不再复制，算作已导出，所以中断后再导出一次就是续传，不会多出 `(2)`。
- **按收藏夹分子文件夹**：范围是某个收藏夹时只有这一个文件夹；否则照片在几个收藏夹里就放进几个，不在任何收藏夹里的放进“未归入收藏夹”。**保持原目录**：`卷名/原来的目录/`。
- **只导出 RAW / JPEG**：选的格式没有、或者所有在线位置都读不到时，改导出另一种（“没有 RAW 的导出 JPEG”）。
- 导出保留原文件的修改时间；目标盘写满或没有权限时整个导出停下并报告。
- **100% 放大**读 JPEG 优先（快十倍以上，和预览一致），JPEG 长边不到 RAW 的九成才读 RAW。翻页时保持 100% 和同一位置；Esc 先退出放大。**单击照片放大到单击处**（回应“照片无法放大”的反馈，用户 2026-11-20 确认保留）：放大到 **50%**，适合窗口已经不小于 50% 时放大到 100%；照片边缘不滚进画面，单击靠边时停在能到的最近处。`Z` 仍是 100%。放大时单击回到适合窗口。

### 7.3 观看体验（M3 之后，用户反馈 V-1–V-4）

- **背景与边框（V-1）**：见 §6。中灰约是 18% 灰卡的亮度；白底上信息条换成浅色外观。默认深灰、有边框、窄留白，用户走查后可以改默认值。
- **任意缩放（V-2）**：比例以 100%（一个图像像素对一个屏幕像素）为准，比较视图各格共用比例和中心。`⌘+` 从适合窗口跳到比它大的第一档；`⌘−` 下一档不比适合窗口大时回到适合窗口。捏合最大 400%，捏到适合窗口以下就回到适合窗口。适合窗口时捏合，松手后从捏合处放大。放大时角上显示比例，如“150% · DSC01066.JPG（卡名）”。
- **单张视图换原图（V-3）**：按照片在屏幕上的长边像素解码（窗口 1440×900 的 Retina 屏上约 1,840 像素，不解完整的 7,008），读 JPEG 优先，规则同 100% 放大。屏幕上用不到比 1600 预览大一成以上的图（小窗口、竖拍照片、非 Retina 屏）就不读。内存里只留焦点和前后各一张，回到网格时全部放掉。信息条上写着正在看的是“原图”还是“预览”。放大时先放大已经换上的原图，再等完整原文件。
- **照片尺寸（V-4）**：照片的宽高以生成预览的那个文件为准（JPEG 优先）。机内 16:9 裁切时 JPEG 是 7008×3944、RAW 是 7008×4672，以前合组时记的是先扫到的 RAW。已有的库在启动时按 480 缩略图的比例校正一次（短边可能差一两个像素，只用于排版），做过记在 `library_meta`，不再重复。

### 7.4 M4 实现时定下的细节（清卡与无卷关联照片）

- **入口**：卷的标题行“N 张缺副本”（按记录算，离线卷上的副本也算有副本）、“⋯”菜单和侧栏右键菜单里的“清卡检查…”“移除卷…”；菜单“图库 → 无卷关联照片…”打开单独的窗口。
- **补副本的目标**：在线的其他卷；文件夹必须在那个卷的扫描文件夹里，不然以后重扫看不到这些副本。复制完只扫描目标文件夹，别的目录不下结论。目标卷正在扫描时不开始。
- **补到一半再补**：目标里已有逐字节相同的同名文件，不再复制、不换子目录，照样登记。补副本时发现源文件已不在（卡还挂着），和导出一样把位置改为历史。
- **副本对不上**（大小和上次扫描时不同、读不了）：不算核实，原样报告，位置不动。预览生成失败的照片也算“没就绪”。
- **移除还插着的卡**：拔出之前不再提示“检测到新卷”。没做清卡检查就移除时，确认框说明是按记录算的。
- **删除无卷关联照片**：已移除、而且一个位置都不剩的卷，记录一并删掉。删掉的照片的撤销记录和图片缓存一起清掉（编号可能被以后导入的照片重新用上）。

## 8. 典型场景（原型必须走通）

单卡 → 按时间倒序 → 边看边打星、打标签 → 筛选“经典 + 5 星” → 全选 → 新建收藏夹 → 在收藏夹里增减 → 导出原文件。

原生应用中，导出之前的部分在 M2 验收，含导出的完整流程在 M3 验收。

## 9. 外部接口

- 命令行工具 `photoai`：按文件名、去扩展名的文件名或编号（含范围）批量打星、批量加入或新建收藏夹，供 Claude skill 调用。
- 编号命中多张时取拍摄时间最晚的一张，输出里列出被跳过的和匹配不到的。只匹配可见照片。
- 默认在软件关闭时使用。软件按字段写入、窗口获得焦点时检查外部改动；其余副作用接受。
- M5 实现时定下的细节（产品规则没变）：
  - 三个命令：`photoai find`（只查）、`photoai rate <0-5>`（0 是去掉星级）、`photoai collect "<名字>"`（没有这个名字就新建，新建和加入在同一个事务里）。匹配项可以写多项，空格或逗号隔开。
  - 带扩展名的文件名（`DSC01926.ARW`）要求这张照片真的有这个扩展名的文件，否则算没匹配到；不是图片扩展名的点当作文件名的一部分。超过 9 位的纯数字当文件名，不当编号（和导入时提取编号的规则一致）。
  - “取最晚的一张”对名字同样适用：名字相同、拍摄时间不同的是两张照片。被一项跳过、又被另一项选中的不算跳过。
  - 编号范围起点不能大于终点；相机编号从 9999 绕回 1 时写成两段（`9990-9999 1-10`）。范围里没匹配到的编号合并成一段段列出。
  - 收藏夹名字完全一样才算同一个；有两个同名收藏夹时报错，不猜。
  - 退出码：0 有匹配；2 一张都没匹配到，什么都没写；1 参数或库出错。软件开着时在错误输出里提示，命令照样执行。
  - skill 在仓库的 `Skills/photoai/`，`Scripts/install-cli.sh` 把命令行装到 `~/.local/bin`、把 skill 链接到 `~/.claude/skills/photoai`。

### 10.1 M6 实现时定下的细节

- **分析用本机的 1600 预览**，不读原片：卡拔掉也能做，和预览一样只做一次。只分析可见照片；预览还没好的等预览。
- **人物识别用 ArcFace 模型**（用户 2026-11-20 选定）。实测系统 Vision 的通用图像特征在真实库的 893 张脸上是按墨镜款式、帽子、男女老少分组的，不能认人；系统没有公开的认人接口。模型是 InsightFace 的 ArcFace R50（`buffalo_l` 里的 `w600k_r50`），协议只允许非商业用途，**不进公开仓库**：`Scripts/install-face-model.sh` 下载后在本机转成 Core ML，放在 `~/Library/Application Support/PhotoAI-Mac-v2/Models/`。没装时人物分析不跑，人物页说明怎么装。
- **找脸和对齐**：Vision 找脸和五官，按两眼、鼻尖、两嘴角摆正成 112×112 再算 512 维特征。脸在 1600 预览上不到 48 像素宽、或 Vision 的拍摄质量低于 0.15（糊、背光、侧过去）时只记位置，不认人。macOS 27 上新的 Swift 版找五官接口多数脸给出框外的点，用旧接口（`VNDetectFaceLandmarksRequest`）。
- **分组**：每个人物用它所有脸的平均方向代表；新脸和它足够像（余弦 ≥ 0.4）就归进去，都不像就自成一个未命名的人物；彼此很像（≥ 0.5）的未命名人物合并。两个有名字的人物从不自动合并；用户的决定（名字、“不是 TA”）不被后台推翻。真实库上和全量层次聚类的结果几乎一样，阈值 0.3–0.5 分出的组差别很小。
- **人物页的操作**：起名字；给两个人起同一个名字就是合并；在某人的页面选中照片点“不是 TA”，这些脸拿出来、以后不再自动归给 TA（可能归给别人）；隐藏（多是路人），隐藏的不出现在人物页，也不能按名字搜。只出现一两次的人默认收起。侧栏“人物”下列出起了名字的人。
- **OCR**：Vision 文字识别，简体、繁体、英文；置信度低于 0.3 的行不要。文字用 FTS5 trigram 索引，中文不用分词，任意一段都能搜到。
- **地点**：坐标取两位小数（约 1 公里）为一个网格，一个网格查一次 Apple；城市名（“杭州市”）做侧栏和检查器的名字，完整地址用来搜索。两次请求之间隔 1.5 秒；连续失败 5 次（没联网、被限流）这一轮先停，下次启动重试。菜单“图库”里打开，默认关闭。
- **交互优先**：用户按键、点击、滚动、捏合后 0.6 秒内，分析先停一停。
- **暂停、续跑**：状态栏和“图库 → 后台任务…”面板里每种分析可以暂停 / 继续；暂停记在本机设置里，重启后仍然暂停；做到哪张记在库里，重启后接着做。
- **搜索**：搜索框在工具栏（`⌘F`），回车后按本地规则认条件：日期 → 标签 → 人名 → 相机 → 镜头 → 编号 / 文件名 → 地名 → 其他文字（OCR 和文件名）。`2026-08` 是日期不是编号范围；`70-200` 是镜头（库里有这支镜头时）；四位数字是编号，年份写 `2026年`；`8月12日` 是每年的这一天；引号里的是一整段文字。条件变成标题行里的标签，可以逐个删除，条件之间取“并且”。所有搜索共用一份筛选条件，每次新搜索从空的筛选开始。Foundation Models 的自然语言输入这次没做。
- **删除无卷关联照片**时，它们的脸、OCR 文字一起删掉，人物的张数跟着变。
