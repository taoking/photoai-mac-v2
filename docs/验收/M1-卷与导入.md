## 3. 插卡导入的完整流程 — 真实卡 NOT RUN，FAT32 磁盘映像 PASS

没有真实卡，用 `hdiutil` 建一个 1 GB 的 FAT32（MBR）磁盘映像代替：系统把它当作可移除的卷挂在 `/Volumes/PHOTOCARD`，有自己的卷 UUID，文件时间是 FAT 的精度。卡上放 3 组大疆 DNG + JPG 和 1,000 张 1200 px 的 JPEG（`DCIM/100MEDIA`、`DCIM/101MEDIA`）。库放在临时目录（`PHOTOAI_LIBRARY_DIR`），不碰真实的库。

```sh
photoai dev-import /Volumes/PHOTOCARD      # 第一次
hdiutil detach … && hdiutil attach …       # 拔掉再插上
photoai dev-import /Volumes/PHOTOCARD      # 第二次
```

## 4. 性能（十万条合成数据）

合成库：`photoai dev-synth <目录> 100000`，10 万张照片、6 个卷、30% 有两处副本、一半是 RAW + JPEG，预览文件是 48 张真实 JPEG 的硬链接（解码开销和真实预览一样）。生成用时 54 秒，数据库 74 MB。

### PF-1 冷启动到网格可见（≤ 2 秒）— PASS（常规启动）

计时从内核记录的进程启动时间开始，到第一屏所有缩略图都画出来为止（`PHOTOAI_MEASURE=1`）：

```text
PF-1 进程启动到窗口出现：140 ms
PF-3 首次加载：192 ms，100000 张
PF-1 第一屏要等 6 张缩略图（可见格子 6 个）
PF-1 冷启动到网格可见：361 ms，100000 张
```

连续多次：359、361、398、403、413、415 ms。

**需要说明的情况：** 每次重新构建后的**第一次**启动，测到 567、999、1080、1106、2202、2420、3620 ms。拆开看，多出来的时间都在我们的代码运行之前，例如一次空库启动“进程启动到窗口出现”就用了 4,504 ms（之后同样的启动是 143 ms）。这是系统第一次见到新签名的程序时做的检查，安装好的应用日常启动不会每次都有。没法在这台机器上清空系统文件缓存（需要 `sudo purge`），所以**重启后的真正冷启动 NOT RUN**，请用户在重启电脑后第一次打开时看一眼。

## 5. 复现方法

```sh
swift test                                                   # 32 项
swift build -c release
.build/release/photoai dev-synth /tmp/synth100k 100000       # 合成十万条库（约 1 分钟）
PHOTOAI_PERF_LIBRARY=/tmp/synth100k swift test -c release --filter PerformanceTests
Scripts/build-app.sh                                         # 生成 .build/PhotoAI-v2.app
PHOTOAI_LIBRARY_DIR=/tmp/synth100k PHOTOAI_MEASURE=1 PHOTOAI_QUIT_AFTER_LAUNCH=1 \
    .build/PhotoAI-v2.app/Contents/MacOS/PhotoAIApp          # PF-1
PHOTOAI_LIBRARY_DIR=/tmp/synth100k PHOTOAI_MEASURE=1 PHOTOAI_SCROLL_TEST=1 \
    .build/PhotoAI-v2.app/Contents/MacOS/PhotoAIApp          # PF-2 替代测量
PHOTOAI_LIBRARY_DIR=/tmp/synth100k PHOTOAI_MEASURE=1 PHOTOAI_SWITCH_TEST=1 \
    .build/PhotoAI-v2.app/Contents/MacOS/PhotoAIApp          # PF-3

photoai dev-audit                                            # 拔掉后核对离线预览
```
