# M5 验收：命令行工具 + skill

> 分支 `m5-cli`（从 `main` 分出，PR 对 `main`），记录日期 2026-11-20。对照 [计划 · M5](../计划.md) 逐项记 **PASS / NOT RUN / BLOCKED**，附命令和输出。
> 机器：Apple Silicon（MacBook Air），macOS 27.3，Xcode 27.0，Swift 6.4，内置 SSD。真实照片：M1 导入的索尼 A7C II 卡的库（2,148 组 ARW + JPG），用副本，**不需要卡插着**。

## 结论

`photoai find` / `rate` / `collect` 做完，匹配规则写在 `PhotoAICore`（`Matching.swift`），软件和命令行共用一份；软件窗口获得焦点时检查外部改动（M2 已有）这次用真实的命令行进程验证。Claude skill 在 `Skills/photoai/SKILL.md`。

- 自动测试 **84 项 PASS**（新增匹配规则 5 项）。
- 软件里走命令行场景（`PHOTOAI_SCENARIO=cli`，真实库的副本）：**17 项 PASS**。软件关闭时打星、加收藏夹后打开软件；软件开着时跑命令行，切回窗口前不变、切回后刷新。
- 十万条合成库上每个命令 7–23 ms（含进程启动）。

**NOT RUN：** skill 装进 Claude 后用自然语言调用一次（安装脚本要写 `~/.local/bin` 和 `~/.claude/skills`，这次的会话没有权限，留给用户，见第 4 节）；真实库上的编号循环（真实卡 2,148 张编号没有重复，编号从 9999 绕回 1，只有自动测试覆盖）；用户本人用 skill。

## 1. 自动测试

```text
$ swift test
✔ Test run with 84 tests in 10 suites passed after 1.808 seconds.
```

新增 `Tests/PhotoAICoreTests/MatchingTests.swift`：

| 测试 | 覆盖 |
| --- | --- |
| `parsesTerms` | 文件名 / 去扩展名的文件名 / 编号（含前导 0）/ 范围；起点大于终点报错；不是图片扩展名的点、超过 9 位的纯数字当文件名；逗号和空格分隔 |
| `matchesFileNameBaseNameAndNumber` | 不分大小写；RAW + JPEG 是一张；有照片但没有这个扩展名的文件算没匹配到；范围里没匹配到的合并成段（`1924-1925`、`1928-1929`、`1931-1932`）；几项命中同一张只算一次 |
| `numberCycleTakesLatestVisible` | 同号三张（2019 年的 DSC01926、2024 年的 IMG_1926、2026 年的 DSC01926）取 2026 年的，跳过按时间从新到旧列出；同名不同时间同样取最晚；被一项跳过又被另一项选中的不算跳过；没有拍摄时间的也能按编号找到；新卡移除后同号只剩旧照片可见，就选旧的；隐藏照片的名字算没匹配到 |
| `rateAndCollect` | 打星；`collect` 新建（名字去掉两头空格）、再加一次只算新加入的；重名报错不猜；空名字报错 |
| `cliAndAppWriteDifferentFields` | 两个连接：软件写 Pick 和标签，命令行写星级和收藏夹，互不覆盖；软件那边的 `data_version` 变了；软件后写同一字段，命令行读到的是后写的值 |

## 2. 软件里的场景（`PHOTOAI_SCENARIO=cli`）

```sh
Scripts/m5-cli-test.sh <工作目录>
```

脚本复制真实库（`.backup` + `cp -cR` 克隆预览），从最新的照片里挑匹配项，软件关闭时先跑命令行，再打开软件走场景。命令行用 release 构建的二进制，软件用 `Scripts/build-app.sh` 构建的 `.app`。

```text
== 软件关闭时：photoai rate 3 / collect，匹配项 DSC01065 1066,1064 1056-1059
已设为 ★3：7 张
  DSC01065.ARW+JPG  2026-11-18 15:40:37  无星  → ★3
  …
新建收藏夹「命令行·关闭时」：新加入 7 张
== 打开软件，开着时的匹配项 1035-1039
PASS 有命令行工具（PHOTOAI_CLI）
PASS PHOTOAI_CLI_CLOSED 匹配到 7 张
PASS 打开软件后这些照片是 3 星
PASS 侧栏有「命令行·关闭时」，7 张
PASS 撤销记录是空的
PASS PHOTOAI_CLI_OPEN 匹配到 5 张，都还不是 4 星
PASS 软件里的两次改动可以撤销
  命令行：已设为 ★4：5 张
PASS 命令行两次都成功
PASS 命令行提示软件正开着，但不阻止：提示：PhotoAI 正开着。改动在切回软件窗口后显示，软件里的撤销记录会清空。
PASS 窗口没重新获得焦点前，界面里的星级不变
PASS 撤销记录还在
PASS 命令行打的 4 星显示出来
PASS 侧栏出现「命令行·开着时」，5 张
PASS 别的进程改过库：撤销记录清空
PASS 软件打的 2 星还在
PASS 软件标的 Pick 还在（命令行只写星级）
PASS 软件自己的改动不算外部改动，撤销记录保留
场景 cli：17 项 PASS，0 项 FAIL
```

说明：

- 命令行是场景里用 `Process` 起的真实子进程，和软件是两个进程、两个数据库连接。
- “切回窗口”是在主窗口上发 `NSWindow.didBecomeKeyNotification`，走的是 `PhotoAIApp` 里同一个 `onReceive` → `windowDidBecomeKey()`。没有真的切到别的应用再切回来：从终端启动的场景不一定能成为前台应用（观看体验验收记录第 5 节）。真的切换留给用户走查。
- 软件开着时打星是“同一字段后写的赢”：命令行写在软件之后，所以显示命令行的 4 星；软件撤销更早的评分会覆盖命令行的改动（产品定位 §3.4 已接受），但撤销记录在切回窗口时已经清空，不会发生。

## 3. 命令行的输出与速度

真实库副本（2,148 张，编号 1–1066 和 8857–9999，没有重复）：

```text
$ photoai find 1-99999
匹配到 2148 张：
  …（只列前 100 张）
没有匹配到：773、868、932、1067-8856、8867、8968-8969、9012、…
```

十万条合成库（`photoai dev-synth <目录> 100000`），`time` 含进程启动：

| 命令 | 用时 |
| --- | --- |
| `find 1926` | 0.007 秒 |
| `rate 4 1926-1950 DSC01999.ARW nosuch 99999999`（26 张，2 项没匹配到） | 0.021 秒 |
| `collect "测试精选" 1-3000`（新建，3,000 张） | 0.023 秒 |

`photos(file_number)` 和 `photos(base_name COLLATE NOCASE)` 两个索引是这次加的（`user_version` 4）。

## 4. skill

- `Skills/photoai/SKILL.md`：三个命令、匹配规则（含编号绕回要写两段）、先 `find` 再改、跳过和没匹配到的一定要告诉用户、退出码、软件开着时的提示、`PHOTOAI_LIBRARY_DIR` 只在用户要求时设。
- `Scripts/install-cli.sh`：release 构建 `photoai` 复制到 `~/.local/bin`（已在 PATH 里），把 `Skills/photoai` 链接到 `~/.claude/skills/photoai`；`--uninstall` 卸载。安装前确认过这两个位置原来都没有东西。
- **NOT RUN**：这次的会话没有权限写仓库外的这两个位置，没装上，也就没用 Claude 实际调用过。用户运行 `Scripts/install-cli.sh` 后，在任意目录对 Claude 说“把 1035 到 1039 打 4 星”之类即可试。**装好后命令行改的是真实的库**；想先在副本上试，设 `PHOTOAI_LIBRARY_DIR` 指向 `Scripts/m5-cli-test.sh` 生成的 `lib-m5`。
