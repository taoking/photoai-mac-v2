- PF-3（收藏夹）、PF-8 PASS。

| `filterRules` | 至少 / 正好、同类“或者”、不同类“并且”、无标签、文件类型、未标记、筛选摘要 |

## 4. 1,000 张连续打星 — PASS

`PHOTOAI_SCENARIO=cull1000`：全部照片、单张视图、自动前进开，每 40 ms 按一次 1–5（每秒 25 张，比人快得多），共 1,000 次。PF-6 从按键到这一轮界面更新完；PF-7 从翻页到下一张的 1600 预览画出来。

| 库 | PF-6（1,000 次） | PF-7（1,000 次） |
| --- | --- | --- |
| 真实照片（2,148 张，真实 1600 预览） | 中位 19.2 ms，95% 22.6 ms，最大 65.7 ms，超过 50 ms 1 次 | 中位 19.2 ms，95% 22.6 ms，最大 84.5 ms，超过 100 ms 0 次 |
| 十万条合成库（约一半已有星级） | 中位 21.9 ms，95% 25.3 ms，最大 38.2 ms，超过 50 ms 0 次 | 中位 21.9 ms，95% 25.4 ms，最大 58.3 ms，超过 100 ms 0 次 |

两次都检查了 1,000 张都打上星、焦点前进了 1,000 张。

**测试中发现并修正的问题：** 第一次在合成库上跑，只前进了 928 次。原因是照片已经是 3 星时再按 3，改动为空，代码直接返回，连自动前进也跳过了，选片会卡在这类照片上。改为：值没变时不写库、不进撤销，但照样提示和自动前进（按键就是确认这一张）。场景里加了“按下和现有相同的星级也自动前进”“值没变时不产生撤销记录”两项。

## 6. 和原型的差别

| 项目 | 处理 |
| --- | --- |
| `Z` 放大到 100% | 移到 M3：要读原文件，和导出一样是发现原片缺失的时机（设计稿 §4.1），一起做 |
| 比较视图的同步缩放、平移 | 随 `Z` 移到 M3 |
| `⌘E` 导出、`⌘F` 搜索 | 按计划在 M3、M6 |
| 已经是这个值时再按一次 | 原型每次都记一条撤销；原生版不写库、不进撤销，但照样自动前进 |

## 8. 已知问题

- 单张视图的信息条、比较视图的提示文字在专注模式里也显示，和原型一样；如果觉得多余，用户走查时再定。
- 切换侧栏项时第一张自动选中（原型的做法），检查器随之显示它的详情。
- 撤销记录只在本次运行内；窗口重新获得焦点时发现别的进程改过库，撤销记录清空（“改动前”的值已经不可信）。
- M1 的已知问题仍在：侧栏列表的 SwiftUI 重入警告、“忽略”过的卷只在本次运行内不再提示、格子拉伸填满整行。
