# M3 验收：导出

> 分支 `m3-export`（从合并了 M2 的 `m1-volumes-import` 分出），记录日期 2026-11-19。对照 [计划 · M3](../计划.md) 逐项记 **PASS / NOT RUN / BLOCKED**，附命令和输出。
> 机器：Apple Silicon，macOS 27.3，Xcode 27.0，Swift 6.4，内置 SSD。真实照片：M1 导入的索尼 A7C II 卡（exFAT，USB 读卡器），2,148 组 ARW + JPG，ARW 平均约 70 MB、JPG 约 6 MB。

## 结论

导出面板（范围 × 文件 × 目录结构）、只复制不覆盖、同名改名、依次尝试在线位置、读不到的位置改为历史、离线卷跳过、`Z` 放大到 100%、比较视图同步平移都做完了。

- 自动测试 58 项 PASS（新增导出与读原片 15 项）。
- 软件里用真实卡和两个测试磁盘映像走导出与放大的场景：**48 项 PASS**。M2 的场景回归：典型场景 70 项、重启核对 7 项、1,000 张连续打星都 PASS。
- 导出的文件和卡上的原文件逐字节相同、修改时间相同；卡上的源文件大小和修改时间与导入时记录的一致。
- PF-9 基线：读卡导出约 **92 MB/s**，瓶颈是读卡器。

**NOT RUN：** 用户本人走查手感（导出面板、`Z` 和单击放大、拖动平移）；导出途中真的拔卡；面板开着时插拔卷、看“需要的卷”即时更新（用的是同一份 `ExportPlan` 计算，计算本身已验）。

| 测试 | 核对了什么 |
| --- | --- |
| `copiesEveryFileWithoutTouchingSources` | 4 个文件全部导出；源文件导出前后 SHA-256 和修改时间不变；目标内容与源相同，保留修改时间；计数一致 |
| `fileChoiceFallsBackToTheOtherKind` | 只导 RAW：没有 RAW 的导 JPEG；只导 JPEG：没有 JPEG 的导 RAW |
| `neverOverwritesAndKeepsPairsTogether` | 目标已有另一张 `DSC00001.JPG`：一字节不动，新导出的 RAW 和 JPEG 都叫 `DSC00001 (2)`；再导一次也不覆盖 |
| `retryAfterInterruptionSkipsFilesAlreadyCopied` | 复制完第一张后取消：只计确实写完的文件，目标里没有半截文件；放一个上次残留的 `.photoai-part`，再导出时清掉，已导出的算“已有相同”，不多出 `(2)` |
| `triesTheNextOnlineLocationAndMarksMissingOnesHistorical` | 卡上的文件被删、备份盘上还有：从备份盘导出；卡上的位置改为历史，照片仍可见，计数一致 |
| `photoWithNoReadableLocationFailsAndBecomesUnlinked` | 唯一的位置读不到：这个文件记为失败，照片进入“无卷关联照片”，星级还在 |
| `rawMissingExportsTheJpegOfThePair` | RAW 被删、只导 RAW：改导 JPEG，RAW 的位置改为历史 |
| `unmountedVolumeIsNotTreatedAsDeletedFiles` | 卷已经不挂着时路径消失：报告失败，**不**改为历史 |
| `changedFileIsReportedButKeptPresent` | 文件大小和上次扫描时不同：报告“大小变了”，不导出、不改位置 |
| `offlinePhotosArePlannedAndSkipped` | “需要的卷”：在线卷 3 张、离线卷 1 张；导出时跳过离线的那张，不改它的位置 |
| `layoutsByCollectionAndOriginalFolders` | 按收藏夹：照片在两个收藏夹里就进两个文件夹，不在的进“未归入收藏夹”，名字里的 `/` 换成 `-`；范围是收藏夹时只有它；保持原目录是 `卷名/DCIM/100MSDCF/` |
| `unwritableDestinationStopsTheExport` | 目标没有写权限：整个导出停下，报告 3 张没导出，什么都没写 |
| `numberedNames` | `DSC00001 (2).ARW`、没有扩展名、文件夹名清理 |
| `picksTheLargestReadableFileAndReportsMissingLocations` | 100% 放大：小 JPEG 和大 RAW 时用 RAW；途中发现不在的位置报出来；卷不挂着时不报“不在” |
| `prefersTheJpegWhenItIsAboutAsLargeAsTheRaw` | 机内 16:9：JPEG 长边和 RAW 一样时用 JPEG，即使 RAW 排在前面 |

## 2. 真实卡导出（命令行，和软件同一套代码）

## 5. 实现中发现、记下的事

- **照片尺寸记的是 RAW 的。** 机内 16:9 裁切时 JPEG 7008×3944、RAW 7008×4672，合组后 `photos.width / height` 记成 3:2。真实卡 2,148 张里 1,266 张如此（480 缩略图比例和记录相差超过 2%）。网格按缩略图本身的比例画，不受影响；胶片条宽度、单击放大的位置换算受影响，M3 的放大已改用画出来的图的比例。修正排进[计划 · M3 之后](../计划.md) V-4。
- **读不到原片的判定。** 拔卡时挂载点下的路径也会消失，所以只有“卷 UUID 仍对得上、文件不存在”才改为历史；读错、权限、大小变了只报告（设计稿 §7.2）。
- **导出的“当前结果”可能是十万张**：面板在后台读位置，按 4,000 张一组查。
