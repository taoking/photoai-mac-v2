# M6 验收：后台分析与搜索

> 分支 `m6-analysis`（从 `main` 分出，PR 对 `main`），记录日期 2026-11-20。对照 [计划 · M6](../计划.md) 逐项记 **PASS / NOT RUN / BLOCKED**，附命令和输出。
> 机器：Apple Silicon（MacBook Air），macOS 27.3，Xcode 27.0，Swift 6.4，内置 SSD。真实照片：M1 导入的索尼 A7C II 卡的库（2,148 组 ARW + JPG），用副本，**不需要卡插着**（分析用本机预览）。

## 结论

OCR、人物（ArcFace 特征入库、自动分组、命名 / 合并 / “不是 TA” / 隐藏）、地点（默认关闭）、全局搜索、后台任务面板做完。人物识别模型按用户的选择用 InsightFace 的 ArcFace R50，不进仓库，`Scripts/install-face-model.sh` 在本机下载并转成 Core ML。

- 自动测试 **93 项 PASS**（新增 9 项：搜索解析 2、搜索结果 1、OCR 队列暂停续跑 1、分组 1、人物操作 1、删除照片时清理 1、地点 1；十万条合成库上的搜索性能 1 项，要设 `PHOTOAI_PERF_LIBRARY` 才真跑）。
- 软件里走分析场景（`PHOTOAI_SCENARIO=analysis`，真实库的副本）：**31 项 PASS**。
- PF-12：**PASS**。后台分析照常开着（用户操作时让路）和关着比，PF-2、PF-6、PF-7 在测量波动之内（第 3 节）；不让路的最坏情况下 PF-6 明显变差，说明让路是必要的。按人的节奏打星时 PF-6 约 50 ms，分析关着也一样，是已知的 P-1。

**NOT RUN：** 地点用真实照片验证（真实库的照片都没有 GPS；用假的地理编码器测了规则，用 Apple 的接口单独查了几个坐标，见第 5 节）；Foundation Models 的自然语言搜索（这次没做）；用户本人走查搜索（人物分组用户已走查：“人物识别这块的效果非常好”）。

## 0. 方案摸底（写代码之前）

在真实库的 1600 预览上先试了几样东西，结论决定了方案：

| 试什么 | 结果 |
| --- | --- |
| 有多少照片有人脸、有字 | 前 300 张：96 张有脸（宽 > 40 像素），只有 1 张认出字（“网络文 / 养基地”）；找脸约 23 ms / 张，OCR 约 135 ms / 张 |
| 系统 Vision 的通用图像特征（`GenerateImageFeaturePrintRequest`）能不能认人 | 不能。2,148 张里 893 张脸，平均连接聚类后各组是“戴同款墨镜的不同女士”“戴眼镜的不同男士”“老年男士”，同一个人换副墨镜被分开 |
| ArcFace R50（转成 Core ML） | 能。740 张有特征的脸，阈值 0.3 / 0.4 / 0.5 分出 112 / 122 / 134 组，最大几组的张数几乎不变（156、122/124、81、74…）；同一个人戴墨镜、眼镜、帽子仍在一组；剩下一组 6 张模糊杂脸，拍摄质量都在 0.06 左右 |
| 增量分组（按人物平均方向，每批 50 张脸） | 和全量层次聚类基本一样（153、124、82、73、67、33…），711 张脸 0.01 秒 |
| 新的 Swift 版找五官接口 `DetectFaceLandmarksRequest` | 77 张脸里 69 张的特征点在框外（如瞳孔在 (-7.2, 6.4)），先给框再找五官也一样；旧接口 `VNDetectFaceLandmarksRequest` 只有 2 张，改用旧接口，坏点的脸只记位置 |
| Apple 反向地理编码（`MKReverseGeocodingRequest`） | 杭州西湖、北京、上海的坐标都返回中文城市名（“杭州市”）和完整地址；东京那次返回 `GEOError -8`（看起来是限流），所以连续失败时先停、下次再试 |

模型转换：`Scripts/install-face-model.sh` 下载 `buffalo_l.zip`（275 MB，SHA-256 `80ffe37d…b0ca2f`），取出 `w600k_r50.onnx`，在 uv 的临时环境（Python 3.12、torch 2.5.1、onnx2torch 1.5.15、coremltools 8.3.0）里转成 Core ML 并编译：

```text
PyTorch 与 Core ML 输出的余弦相似度：0.9985
模型 → ~/Library/Application Support/PhotoAI-Mac-v2/Models/ArcFace-R50.mlmodelc
```

## 3. PF-12：后台分析开和关

```sh
Scripts/test/m6-pf12.sh <工作目录>
```

同一份数据（真实库副本，分析从头开始）、同一台机器、同样的操作，三种设置各跑一遍：**关**、**开（照常，用户操作后 0.6 秒内让路）**、**开（不让路，最坏情况）**。PF-2 是程序滚动，分析看不到“用户在操作”，三种情况下分析都在跑；打星场景每次调命令前记一次“用户在操作”，和真按键一样。

第二轮（最终代码）：

| 测量 | 关 | 开（照常） | 开（不让路） |
| --- | --- | --- | --- |
| PF-2 滚动 600 帧，主线程中位 / 95% / 最大，超过 16 ms 的帧 | 1.12 / 1.53 / 7.73 ms，0 | 1.23 / 1.58 / 8.58 ms，0 | 1.27 / 1.67 / 9.03 ms，0 |
| PF-6 打星，每 40 ms 一次 × 1,000，中位 / 95%，超过 50 ms | 14.3 / 43.1 ms，11 次 | 13.9 / 42.1 ms，7 次 | 14.6 / 50.7 ms，51 次 |
| PF-7 翻页，同上，中位 / 95% | 14.2 / 43.2 ms | 13.9 / 42.3 ms | 14.5 / 50.9 ms |
| PF-6 打星，每 450 ms 一次 × 150，中位 / 95%，超过 50 ms | 38.0 / 50.1 ms，8 次 | 38.9 / 50.6 ms，9 次 | 42.0 / 62.3 ms，32 次 |
| PF-7 翻页，同上，中位 / 95% | 38.2 / 50.4 ms | 39.0 / 50.5 ms | 41.9 / 62.2 ms |

第一轮（分组还在写事务里做；只有“关”和“不让路”两种，打星场景还没记“用户在操作”，“开”就是不让路）：

| 测量 | 关 | 开（不让路） |
| --- | --- | --- |
| PF-2 中位 / 95% / 最大 | 1.45 / 1.70 / 8.06 ms | 1.23 / 1.51 / 7.96 ms |
| PF-6 每 40 ms，中位 / 95% | 6.7 / 15.1 ms | 12.8 / 15.9 ms |
| PF-6 每 450 ms，中位 / 95%，超过 50 ms | 32.9 / 41.4 ms，1 次 | 37.0 / 48.1 ms，4 次 |

- **照常开着和关着在波动之内**：PF-2 每帧多 0.1 ms 左右，PF-6、PF-7 的中位和 95% 差不到 1 ms。**PASS**。
- **不让路时 PF-6 变差**：95% 多 8–12 ms，超过 50 ms 的次数多几倍。Vision 和 Core ML 占着 CPU、GPU 和神经网络引擎，界面的刷新要等。所以“用户操作后 0.6 秒内让路”是必要的，不是可有可无。
- **两轮之间波动很大**：同样是“关”、每 40 ms 一次，第一轮 95% 15 ms，第二轮 43 ms。两轮之间机器的状态不同（第二轮连着跑了九次软件），所以只在同一轮里比较开和关。
- 按人的节奏（450 ms），分析关着时 PF-6 的 95% 也在 50 ms 上下，第二轮这一项 FAIL。这是已知的 P-1（`main` 上一样），不是后台分析引起的，仍在计划里。

## 4. 人物识别的模型

- 模型不在仓库里：`.gitignore` 不需要改，模型在 `~/Library/Application Support/PhotoAI-Mac-v2/Models/`；`PHOTOAI_FACE_MODEL` 可以指到别处。没装模型时人物分析不跑，人物页、后台任务面板说明怎么装（`faceModelMissing`）。没装模型的情况只在代码里处理，没有实际跑过（这台机器装着模型）：NOT RUN。
- 模型协议：InsightFace 的预训练模型只允许非商业研究用途；这是只给自己用的软件，用户知情后选的（沟通记录第 20 轮）。

## 5. 地点

- 规则用假的地理编码器测（第 1 节）：一个网格只查一次、查不到也记下、按城市列出、按地址搜。
- Apple 的接口单独查了几个坐标（第 0 节），中文城市名可用；东京那次失败，所以连续失败 5 次就先停。
- 真实照片：真实库 2,148 张都没有 GPS（`latitude` 全空）。软件里打开地点功能、用真实带坐标的照片验证都 NOT RUN；国内坐标偏移对城市名的影响也没验证（产品定位 §6 提到过）。

## 6. 没做的

- Foundation Models 的自然语言搜索（信息架构 §6 写的是“有 Foundation Models 时可以”）：这次只做了本地规则。
- 原型里人物页还是存根，这次定的人物页操作（命名、同名合并、“不是 TA”、隐藏）没有同步进原型，等用户看过再定。
- 用户本人走查：人物分组 PASS（2026-11-20，用户：“人物识别这块的效果非常好”）；搜索 NOT RUN。
