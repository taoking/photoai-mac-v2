## 1. 验证：能不能读到、读得对不对

索尼把对焦位置写在 MakerNote 里（ImageIO 不解析索尼的 MakerNote，要自己读）：

- `0x2027 FocusLocation`：int16u[4]，图宽、图高、对焦点 X、Y（传感器方向，没转正）；
- `0x2037 FocusFrameSize`：6 字节，框宽、框高、有效标志。人脸 / 眼部追踪时框是人脸那么大（如 745×592），广域、自由点是 153×156 左右的小框。

真实卡（索尼 A7C II）用 exiftool 统计：

```text
2,148 张 JPG 都有 FocusLocation
框大小：153x156 1177、153x154 368、153x153 324、745x592 82、101x101 15 …；n/a（标为无效）3 张
对焦区域：Wide 1167（其中人脸追踪 887）、Flexible Spot 92、Center 2
方向：Horizontal 923、Rotate 270 CW 1225
```

`Sources/PhotoAICore/FocusPoint.swift` 只读文件头的几处（JPEG 找 APP1 Exif；ARW 本身就是 TIFF），走 IFD0 → Exif IFD → MakerNote。JPEG 的 MakerNote 前面有 12 字节 “SONY DSC ” 头，ARW 没有头，所以 ARW 看 IFD0 的厂商是不是 SONY。

核对（`photoai focus <文件>…`）：

```text
4,300 个文件（ARW + JPG，含 4 个 ._ 开头的 AppleDouble 文件）约 6 秒
ARW 和同名 JPG：2149 对，不一致 0
JPG 和 exiftool 的对焦点（转正后的中心）：2148 张，不一致 0（修正伸出画面的大框之前是 1 张）
```

在 4 张照片上把框画出来看过：人脸追踪的竖拍（框在人身上）、自由点（框在清楚的桥上，前景是虚的）、广域、人脸追踪的大框，位置都对。

实现时定下的：

- 框标为无效（3 张，点都在画面正中附近）当作没有记录，不画猜出来的框。
- 伸出画面的人脸大框截掉伸出去的部分，不平移。
- 这台相机根本不记框（没有 0x2037）时给图宽 3% 的方框。

## 2. 软件里

- 库：`photos` 加 `focus_state`、`focus_x/y/w/h`（`user_version` 6，见[数据模型](../../设计/数据模型.md) §11）。启动、扫描完、预览做完时，原片在线就由 `FocusRunner` 在后台读还没读过的；文件读不了的这一轮跳过，下次插上再读。旧照片不用重新导入。
- 显示：`A` 开关（记在本机设置里，默认关）；单张、比较视图适合窗口时是 SwiftUI 叠在照片上的一层，放大时是画布上的 `CAShapeLayer`，线宽随放大比例反着变，屏幕上粗细不变。
- `⇧Z`：单张视图以框的中心放大到 100%；已经放大时移过去；比较视图只提示。
- 检查器直方图下面一行：开关、“放大到对焦点（⇧Z）”或“没有对焦记录” / “原片在线时读取”。框跟详情一起读，翻页时不另外查库。

场景（`Scripts/test/inspector-test.sh`，真实卡插着）：

```text
对焦框：读了 2148 张，3450 ms
PASS 读到对焦框 2145 张，没有记录 3 张，待读 0 张
PASS 找到 DSC01065，对焦框中心 (0.331, 0.450)
PASS A 打开对焦框，记进本机设置：true
PASS 显示的是库里存的框
PASS 放大到 100%：100%
PASS 画面中心 (0.331, 0.450) 对着对焦框 (0.331, 0.450)
PASS 放大后照片上也画着对焦框
PASS 画面中心回到 (0.331, 0.450)
PASS 比较视图里 ⇧Z 只提示，不放大
PASS 再按 A 隐藏对焦框
场景 inspector：25 项 PASS，0 项 FAIL
```

截图看过：适合窗口和 100% 时绿框都在同一处（窗台上那盆花的左边）。

场景抓到一个问题并改了：框还没查到时叠在照片上的那层是空的，SwiftUI 不跑它的 task，框一直不出来（之前是检查器那一行顺带查了才显示）。改成垫一层透明、不接点击的视图。

锁屏时系统截图截不到窗口，`PHOTOAI_SNAPSHOT_SCREEN=1` 没出文件就退回原来的画法；放大的画布在原来的画法里也画框。

## 3. 流畅度

`Scripts/test/inspector-pf.sh`，真实库副本，后台分析关。**这次测的时候屏幕锁着**，PF-6 / PF-7 整体比 0.6.0 记录里的高，所以在同样条件下用 `main`（没有对焦框）重测作对照：

| 项目 | `main` | 对焦框开着，后台在读卡 | 对焦框关着，不读卡 |
| --- | --- | --- | --- |
| PF-2 网格滚动，主线程 95% | — | 1.55 ms，超 16 ms 0 帧 | — |
| PF-6 每 40 ms 一次 1,000 次 | 中位 13.3 ms，95% 40.7 ms | 中位 13.5 ms，95% 42.8 ms | 中位 13.6 ms，95% 42.0 ms |
| PF-7 同上 | 中位 13.2 ms，95% 40.6 ms | 中位 13.4 ms，95% 42.6 ms | 中位 13.5 ms，95% 41.8 ms |
| PF-6 每 450 ms 一次 150 次 | 中位 37.8 ms，95% 48.0 ms | 中位 33.9 ms，95% 47.5 ms | 中位 36.6 ms，95% 49.5 ms |
| PF-7 同上 | 中位 37.6 ms，95% 47.8 ms | 中位 33.6 ms，95% 47.3 ms | 中位 36.3 ms，95% 49.2 ms |

都在波动之内。中间一版检查器那一行每翻一页另外查一次库、改一次缓存，会让检查器多重画一次；改成跟详情一起读。`PHOTOAI_PF_EXTRA="PHOTOAI_FOCUS=off"` 可以不读卡测。
